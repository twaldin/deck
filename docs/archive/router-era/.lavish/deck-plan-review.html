Why (the five diagnosed problems)

1 · Transport is the bug

tmux send-keys + pane-regex caused the incident classes in learnings.md: swallowed Enters, watcher lapses, 13 orphaned shells after OOM. flt died on the same rock.

2 · Chat can't hold a queue

15–30 ticket/PR pairs into one thread ⇒ agent follows the last pivot, drops bg work. Structural, not a prompting failure.

3 · Config hell is multiplicative

3 daily + 6 dormant harnesses × MCP × OAuth × skills × instruction files. Notion reachable 3 ways; ≥9 model OAuth grants; 2 local proxies.

4 · Five meta-layers, no kernel

firstmate, flt, Superset, no-mistakes, robotim each own a slice of spawn-watch-react.

5 · Voluntary bookkeeping fails

fm-effort.sh autopsy: 137 events, one day, all batch ingest, zero agent emissions, board never rendered.

North star

One TUI over all projects. Tim issues intent + stamps merges. Everything else — orchestration included — just happens.

Invariants (hard)

I1Extension-only. pi never forked/patched; everything is extensions + packages + config.
I2One harness has config. Anything else invoked is stateless, zero footprint.
I3Session ≠ state. Manifests + tails on disk are truth; sessions ephemeral, revivable.
I4No voluntary bookkeeping. Records are side effects of hooks, watchers, lifecycle tools.
I5Judgment is agent work, facts are watcher work. The substrate never thinks.
I6Idempotent intake. (source, external_id, version) + cursors; edits are new facts.
I7Tim gates merges. Slack CLI is read+draft only.
I8Plan-limit multi-account pooling is core infra, non-negotiable.
I9All work in worktrees; owners never cd in. One pool, one allocator.
I10Shared trees read-only; Tim's prefs are local overlays (skills visibility, source policy).
I11Network-shaped seams now (machine:session ids, broker on socket); multi-machine later.

Adversarial review — codex / gpt-5.6-sol @ xhigh

Cross-harness pass on PLAN + SPEC. Verdict: request_changes · 10 findings (9 high, 1 medium). SPEC rewritten to v0.2; full report at .lavish/adversarial-report.json.

#FindingDisposition
1Smithers "durable" claim hollow — Deck excludes its SQLite, so abandonment loses run statePartial accept. Corrected the claim (PLAN §5.3): Deck mirrors only side-effect receipts for irreversible ops (§10), not the whole run graph — abandonment cost is real but bounded. Rejected full journal duplication as over-engineering.
2Migration has no exclusive-ownership handoff — firstmate + deck can both act on a PRAccept. New SPEC §16 cutover protocol: freeze→drain→marker→verify→rollback, per-effort.
3Persistence not atomic at op level; crash can split tail/cursor/dedupeAccept concern, reject SQLite-for-v1. Ordered writes (tail-before-cursor) + idempotency keys make the crash window benign (worst case = dropped duplicate, never loss). SQLite stays a measured-volume trigger (SPEC §4.2) — honors your no-DB pushback.
4Exactly-one-owner / exactly-once not enforced; two owners can spawn post-rebootAccept. New SPEC §4.5: per-effort lease + epoch token, CAS on every mutation, side-effect fencing, durable command inbox with ack, cancellation protocol.
5No privilege boundary — same-UID agents reach the whole credential estate; agent-authored JSX = arbitrary codeAccept the gap, partial the fix. SPEC §13 rewritten honestly: same-UID is NOT a boundary (v0.1 was wrong); broker proxies LLM (no raw tokens); tool CLIs get scoped short-lived capabilities. Full sandbox + signed workflows = explicit v2 path, not v1 — keeps your no-overengineer line.
6Merge stamp is convention, not auth — agent can merge a head Tim never approvedAccept + corrected twice. Two-tier model (SPEC §10/§13): split transports (read+PR-write API token + SSH deploy key; deploy keys can't call REST; branch protection) stop the accidental path; the Contents:write merge PAT lives in macOS Keychain behind a per-merge Tim-biometric ACL — the real OS boundary under same-UID. v0.2's "no merge scope" was impossible (merge = Contents:write) and "physically cannot" overclaimed under same-UID; Keychain release is what actually satisfies I7. Unattended merges blocked by construction (consistent with I7).
7Browser matrix controls concurrency, not auth; raw ws_endpoint leaks storage/admin sessionAccept. SPEC §8 rewritten: mediated API (no raw ws_endpoint to workers); privileged domains never cloned; serialization contradiction fixed.
8Broker go/no-go proves quota, not authorization/TOS; needs conformance battery + single-flight refreshAccept. SPEC §6.5 expanded (streaming/tools/thinking/cache/cancel/eligibility/revocation/concurrent-rotation); single-flight refresh §6.3; TOS risk recorded as deliberate human decision §6.7.
9Fresh-owner recovery depends on lost chat state; only 50 events; no charterAccept. Immutable charter + decision ledger in manifest (§3.1); token-budgeted seed preserving root-intent/cards/dispatches/trigger (§4.6); full-tail fallback.
10Resource model doesn't bound the OOM that motivated the rewriteAccept. New SPEC §5.5: poll deadlines+output caps, process-group cancel, global+per-effort admission limits, wake coalescing, RSS budgets, OOM acceptance tests. PLAN §5.2 daemon-count contradiction fixed.

Net: 9 accepted, 1 partial (Smithers), 1 sub-rejected (SQLite-for-v1, concern accepted via ordered writes). Two reviewer asks explicitly declined as over-engineering — documented in SPEC v0.2 changelog.
